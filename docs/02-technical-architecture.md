# وثيقة البنية التقنية لمنصة فحص العقوبات

## 1. المعمارية العامة

### 1.1 نموذج الطبقات الثلاث
المنصة مبنية على نموذج معماري حديث يتكون من ثلاث طبقات رئيسية:

**الطبقة الأولى - الواجهة الأمامية (Frontend)**
تتعامل مع تفاعل المستخدم وعرض البيانات. تم بناؤها باستخدام React 19 و Tailwind CSS 4 لتوفير واجهة مستخدم حديثة وسريسة الاستجابة. تدعم الواجهة اللغات العربية والإنجليزية بشكل كامل مع دعم الكتابة من اليمين إلى اليسار.

**الطبقة الثانية - خادم التطبيق (Backend)**
تتعامل مع منطق الأعمال ومعالجة البيانات. تم بناؤها باستخدام Express.js و Node.js لتوفير أداء عالي وقابلية توسع. تستخدم tRPC للتواصل الآمن والمكتوب بين الواجهة الأمامية والخادم.

**الطبقة الثالثة - قاعدة البيانات (Database)**
تخزن جميع البيانات بما فيها قوائم العقوبات والسجلات والمستخدمين. تم استخدام MySQL/TiDB لتوفير قاعدة بيانات موثوقة وقابلة للتوسع.

## 2. المكونات الرئيسية

### 2.1 محرك البحث (Search Engine)
**الملف**: `server/search-engine.ts`

يقوم محرك البحث بمعالجة استعلامات البحث وإرجاع النتائج. يستخدم عدة تقنيات متقدمة:

- **التطبيع (Normalization)**: تطبيع النصوص العربية والإنجليزية لتوحيد الأحرف والرموز
- **البحث الضبابي (Fuzzy Search)**: استخدام مكتبة Fuse.js للبحث عن الأسماء المتشابهة
- **حساب التشابه (Similarity Scoring)**: استخدام خوارزمية Levenshtein لحساب درجة التشابه بين الأسماء
- **معالجة الأسماء المختلطة**: دعم الأسماء التي تحتوي على كلمات عربية وإنجليزية معاً

**خوارزمية البحث**:
1. تطبيع الاستعلام والبيانات المخزنة
2. البحث السريع باستخدام Fuse.js
3. حساب درجة التشابه لكل نتيجة
4. ترتيب النتائج حسب الدرجة
5. إرجاع أفضل النتائج

### 2.2 معالج الباتش (Batch Processor)
**الملف**: `server/batch-processor.ts`

يقوم معالج الباتش بمعالجة ملفات Excel التي تحتوي على آلاف الأسماء. يوفر معالجة متقدمة وتتبع التقدم:

**خطوات المعالجة**:
1. قراءة ملف Excel وتحليل الأسماء
2. تحميل قوائم العقوبات في الذاكرة للمعالجة السريعة
3. البحث عن كل اسم ضد قوائم العقوبات
4. تصنيف النتائج (MATCH, POSSIBLE_MATCH, NO_MATCH)
5. حفظ النتائج في قاعدة البيانات
6. إنشاء تقرير شامل

**معايير التصنيف**:
- **MATCH**: درجة تطابق >= 85% مع >= 3 كلمات متطابقة
- **POSSIBLE_MATCH**: درجة تطابق 60-84% مع >= 3 كلمات متطابقة
- **NO_MATCH**: درجة تطابق < 60% أو < 3 كلمات متطابقة

### 2.3 مولد التقارير (Report Generator)
**الملف**: `server/pdf-report.ts`

ينتج مولد التقارير تقارير PDF مفصلة لكل عملية فحص. يدعم اللغة العربية بشكل كامل:

**محتويات التقرير**:
- معلومات الفحص (التاريخ، الوقت، المستخدم)
- بيانات السجل المفحوص
- نتائج المطابقة
- درجات التشابه
- الأسماء البديلة
- الجنسية والنوع
- سبب الإدراج
- الإجراءات المتخذة

### 2.4 نظام المصادقة (Authentication)
**الملف**: `server/_core/context.ts`

يستخدم النظام مصادقة OAuth من Manus:
- تسجيل دخول آمن للمستخدمين
- إدارة الجلسات
- التحكم بالصلاحيات (Admin, User)
- تسجيل الأنشطة

## 3. قاعدة البيانات

### 3.1 جداول البيانات الرئيسية

**جدول sanctionsRecords** - قوائم العقوبات
```
- id: معرف فريد
- nameEn: الاسم بالإنجليزية
- nameAr: الاسم بالعربية
- entityType: نوع الكيان (فرد، شركة، سفينة)
- nationality: الجنسية
- listingDate: تاريخ الإدراج
- listingReason: سبب الإدراج
- issuingBody: الجهة المصدرة
- legalBasis: الأساس القانوني
- actionTaken: الإجراء المتخذ
- alternativeNames: الأسماء البديلة
```

**جدول screeningJobs** - سجلات الفحص
```
- id: معرف فريد
- userId: معرف المستخدم
- fileName: اسم الملف
- totalRecords: عدد السجلات
- processedRecords: عدد السجلات المعالجة
- status: حالة المعالجة
- createdAt: وقت الإنشاء
- completedAt: وقت الانتهاء
```

**جدول screeningResults** - نتائج الفحص
```
- id: معرف فريد
- jobId: معرف عملية الفحص
- rowNumber: رقم الصف
- inputName: الاسم المدخل
- status: نتيجة الفحص (MATCH, POSSIBLE_MATCH, NO_MATCH)
- matchScore: درجة التطابق
- matchedRecordId: معرف السجل المطابق
```

### 3.2 الفهارس والأداء
- فهرس على `nameEn` و `nameAr` لتسريع البحث
- فهرس على `entityType` و `nationality` للتصفية السريعة
- فهرس على `userId` و `createdAt` لسجلات الفحص

## 4. التكامل مع الأنظمة الخارجية

### 4.1 التكامل مع البنوك
يتم توفير API آمن للبنوك للتحقق من الأسماء:
```
POST /api/trpc/screening.checkName
{
  "name": "اسم العميل",
  "entityType": "Individual"
}
```

### 4.2 التكامل مع الجهات الحكومية
واجهة ويب آمنة للجهات الحكومية للوصول إلى المنصة مع تسجيل دخول موحد.

### 4.3 تحديث البيانات
تحديثات دورية لقوائم العقوبات من المصادر الدولية:
- تحميل يومي من قوائم الأمم المتحدة
- تحميل أسبوعي من قوائم الاتحاد الأوروبي
- تحميل أسبوعي من قوائم OFAC

## 5. الأداء والقابلية للتوسع

### 5.1 معايير الأداء
- **وقت البحث الفردي**: أقل من 500 ملي ثانية
- **معالجة الباتش**: معالجة 1000 اسم في أقل من 5 دقائق
- **توفرية النظام**: 99.9% على مدار السنة

### 5.2 القابلية للتوسع
- **التخزين المؤقت (Caching)**: استخدام Redis للتخزين المؤقت
- **معالجة متوازية**: معالجة متعددة الخيوط للباتش
- **قاعدة بيانات موزعة**: استخدام TiDB للتوسع الأفقي
