# الوصف الفني العام

## 1. نظرة عامة على المنصة

### 1.1 الهدف الرئيسي
منصة فحص العقوبات (SanctionCheck) هي نظام متقدم لفحص الأسماء والكيانات ضد قوائم العقوبات الدولية والمحلية. تهدف المنصة إلى توفير أداة فعالة وآمنة للجهات المختصة والمؤسسات المالية للتحقق من امتثال العملاء والشركاء التجاريين لقوائم العقوبات.

### 1.2 المستخدمون المستهدفون
- **الجهات المختصة**: البنك المركزي، الجهات الرقابية، الأجهزة الأمنية
- **المؤسسات المالية**: البنوك، شركات الصرافة، شركات التأمين
- **المؤسسات الحكومية**: الجمارك، الهجرة، الجهات الإدارية
- **القطاع الخاص**: الشركات الكبرى والمتوسطة

### 1.3 الميزات الرئيسية
- **فحص فردي**: البحث عن اسم واحد ضد قوائم العقوبات
- **فحص جماعي (Batch)**: معالجة ملفات Excel تحتوي على آلاف الأسماء
- **دعم اللغات**: دعم كامل للعربية والإنجليزية والنصوص المختلطة
- **معالجة الأخطاء الإملائية**: التعامل مع الأخطاء الإملائية والتنويعات
- **تقارير مفصلة**: تقارير PDF شاملة لكل عملية فحص
- **لوحة تحكم إدارية**: إدارة المستخدمين والبيانات والسجلات

## 2. الأهداف والمتطلبات

### 2.1 الأهداف الاستراتيجية
1. **الامتثال القانوني**: ضمان امتثال الجهات المختصة لقوائم العقوبات الدولية
2. **الحماية المالية**: منع تمويل الإرهاب وغسيل الأموال
3. **الكفاءة التشغيلية**: تسريع عملية الفحص وتقليل الأخطاء اليدوية
4. **الشفافية**: توفير سجلات دقيقة وقابلة للتدقيق

### 2.2 المتطلبات الفنية
- **الأداء**: معالجة آلاف الأسماء في دقائق
- **الدقة**: معدل خطأ أقل من 0.1%
- **التوفرية**: توفرية 99.9% على مدار السنة
- **الأمان**: تشفير كامل للبيانات والاتصالات
- **التوافقية**: التوافق مع الأنظمة المصرفية الموجودة

## 3. قوائم العقوبات المدعومة

### 3.1 القوائم الدولية
- **قائمة الأمم المتحدة (UNSC)**: قوائم العقوبات الصادرة عن مجلس الأمن
- **قائمة الاتحاد الأوروبي (EU)**: قوائم العقوبات الأوروبية
- **قائمة الولايات المتحدة (OFAC)**: قوائم العقوبات الأمريكية
- **قائمة المملكة المتحدة (UK)**: قوائم العقوبات البريطانية

### 3.2 القوائم المحلية
- **القوائم الوطنية**: قوائم العقوبات الصادرة عن الجهات المحلية
- **قوائم الإرهاب**: قوائم الأفراد والكيانات المرتبطة بالإرهاب
- **قوائم الفساد**: قوائم الأفراد المدانين بالفساد

## 4. معايير الامتثال

### 4.1 المعايير الدولية
- **معايير FATF**: التوصيات الأربعين من فريق العمل المالي
- **معايير بازل**: معايير بازل للرقابة البنكية
- **معايير ISO**: معايير الأمان والجودة الدولية

### 4.2 المتطلبات المحلية
- **القوانين الوطنية**: القوانين المحلية لمكافحة غسيل الأموال
- **التعليمات البنكية**: تعليمات البنك المركزي
- **لوائح الجهات الرقابية**: لوائح الجهات المختصة

# البنية التقنية

## 1. المعمارية العامة

### 1.1 نموذج الطبقات الثلاث
المنصة مبنية على نموذج معماري حديث يتكون من ثلاث طبقات رئيسية:

**الطبقة الأولى - الواجهة الأمامية (Frontend)**
تتعامل مع تفاعل المستخدم وعرض البيانات. تم بناؤها باستخدام React 19 و Tailwind CSS 4 لتوفير واجهة مستخدم حديثة وسريسة الاستجابة. تدعم الواجهة اللغات العربية والإنجليزية بشكل كامل مع دعم الكتابة من اليمين إلى اليسار.

**الطبقة الثانية - خادم التطبيق (Backend)**
تتعامل مع منطق الأعمال ومعالجة البيانات. تم بناؤها باستخدام Express.js و Node.js لتوفير أداء عالي وقابلية توسع. تستخدم tRPC للتواصل الآمن والمكتوب بين الواجهة الأمامية والخادم.

**الطبقة الثالثة - قاعدة البيانات (Database)**
تخزن جميع البيانات بما فيها قوائم العقوبات والسجلات والمستخدمين. تم استخدام MySQL/TiDB لتوفير قاعدة بيانات موثوقة وقابلة للتوسع.

### 1.2 مكونات النظام الرئيسية

| المكون | الوصف | التقنيات |
|-------|-------|---------|
| **محرك البحث** | معالجة استعلامات البحث | Fuse.js, Levenshtein |
| **معالج الباتش** | معالجة ملفات Excel | Node.js, Excel Parser |
| **مولد التقارير** | إنتاج تقارير PDF | PDFKit, ReportLab |
| **نظام المصادقة** | مصادقة آمنة | OAuth 2.0, JWT |
| **قاعدة البيانات** | تخزين البيانات | MySQL/TiDB |

## 2. المكونات الرئيسية

### 2.1 محرك البحث (Search Engine)
يقوم محرك البحث بمعالجة استعلامات البحث وإرجاع النتائج باستخدام:
- **التطبيع (Normalization)**: تطبيع النصوص العربية والإنجليزية
- **البحث الضبابي (Fuzzy Search)**: استخدام Fuse.js للبحث عن الأسماء المتشابهة
- **حساب التشابه (Similarity Scoring)**: استخدام Levenshtein لحساب درجة التشابه
- **معالجة الأسماء المختلطة**: دعم الأسماء التي تحتوي على كلمات عربية وإنجليزية

### 2.2 معالج الباتش (Batch Processor)
يقوم معالج الباتش بمعالجة ملفات Excel بخطوات:
1. قراءة الملف وتحليل الأسماء
2. تحميل قوائم العقوبات في الذاكرة
3. البحث عن كل اسم ضد قوائم العقوبات
4. تصنيف النتائج (MATCH, POSSIBLE_MATCH, NO_MATCH)
5. حفظ النتائج في قاعدة البيانات
6. إنشاء تقرير شامل

**معايير التصنيف**:
- **MATCH**: درجة >= 85% مع >= 3 كلمات متطابقة
- **POSSIBLE_MATCH**: درجة 60-84% مع >= 3 كلمات متطابقة
- **NO_MATCH**: درجة < 60% أو < 3 كلمات متطابقة

### 2.3 مولد التقارير (Report Generator)
ينتج مولد التقارير تقارير PDF مفصلة تحتوي على:
- معلومات الفحص (التاريخ، الوقت، المستخدم)
- بيانات السجل المفحوص
- نتائج المطابقة ودرجات التشابه
- الأسماء البديلة والجنسية
- سبب الإدراج والإجراءات المتخذة

## 3. قاعدة البيانات

### 3.1 جداول البيانات الرئيسية

| الجدول | الوصف | الحقول الرئيسية |
|--------|-------|-----------------|
| **sanctionsRecords** | قوائم العقوبات | nameEn, nameAr, entityType, nationality |
| **screeningJobs** | سجلات الفحص | userId, fileName, status, createdAt |
| **screeningResults** | نتائج الفحص | jobId, inputName, status, matchScore |
| **users** | بيانات المستخدمين | email, role, createdAt |

### 3.2 الفهارس والأداء
- فهرس على `nameEn` و `nameAr` لتسريع البحث
- فهرس على `entityType` و `nationality` للتصفية السريعة
- فهرس على `userId` و `createdAt` لسجلات الفحص

## 4. التكامل مع الأنظمة الخارجية

### 4.1 التكامل مع البنوك
يتم توفير API آمن للبنوك للتحقق من الأسماء مع تشفير كامل وتسجيل جميع العمليات.

### 4.2 التكامل مع الجهات الحكومية
واجهة ويب آمنة للجهات الحكومية مع تسجيل دخول موحد وتحكم بالصلاحيات.

### 4.3 تحديث البيانات
تحديثات دورية لقوائم العقوبات:
- تحميل يومي من قوائم الأمم المتحدة
- تحميل أسبوعي من قوائم الاتحاد الأوروبي
- تحميل أسبوعي من قوائم OFAC

## 5. الأداء والقابلية للتوسع

### 5.1 معايير الأداء
- **وقت البحث الفردي**: أقل من 500 ملي ثانية
- **معالجة الباتش**: معالجة 1000 اسم في أقل من 5 دقائق
- **توفرية النظام**: 99.9% على مدار السنة

### 5.2 القابلية للتوسع
- **التخزين المؤقت (Caching)**: استخدام Redis للتخزين المؤقت
- **معالجة متوازية**: معالجة متعددة الخيوط للباتش
- **قاعدة بيانات موزعة**: استخدام TiDB للتوسع الأفقي

# آليات العمل والإجراءات التشغيلية

## 1. آلية الفحص الفردي

### 1.1 خطوات الفحص الفردي

**الخطوة الأولى - التحضير والتطبيع**
يتم تطبيع الاسم المدخل بإزالة الرموز الخاصة وتوحيد الأحرف العربية.

**الخطوة الثانية - البحث السريع**
يتم البحث السريع في قاعدة البيانات باستخدام فهارس متقدمة.

**الخطوة الثالثة - حساب درجة التطابق**
لكل مرشح، يتم حساب درجة التطابق باستخدام معايير متعددة.

**الخطوة الرابعة - التصنيف**
بناءً على درجة التطابق وعدد الكلمات المتطابقة، يتم تصنيف النتيجة.

**الخطوة الخامسة - عرض النتائج**
يتم عرض النتائج للمستخدم مع تفاصيل كاملة.

### 1.2 معايير التطابق المتقدمة

**معيار عدد الكلمات المتطابقة**
يتطلب النظام مطابقة **3 كلمات على الأقل** من الاسم المستعلم عنه.

**معيار درجة التشابه**
يتم حساب درجة التشابه باستخدام Levenshtein مع عتبة 80%.

**معيار الأسماء البديلة**
يتم البحث أيضاً في الأسماء البديلة والأسماء السابقة.

## 2. آلية الفحص الجماعي (Batch Processing)

### 2.1 خطوات معالجة الباتش

1. **تحميل الملف**: التحقق من صيغة الملف والأعمدة المطلوبة
2. **التحضير والتحليل**: قراءة الملف وتحليل الأسماء
3. **تحميل البيانات المرجعية**: تحميل قوائم العقوبات في الذاكرة
4. **معالجة متوازية**: معالجة الأسماء بشكل متوازي
5. **تتبع التقدم**: تحديث شريط التقدم في الوقت الفعلي
6. **حفظ النتائج**: حفظ نتائج الفحص في قاعدة البيانات
7. **إنشاء التقرير**: إنشاء تقرير شامل

### 2.2 معايير الأداء

|--------|--------|
| معالجة 1000 اسم | أقل من 5 دقائق |
| معالجة 10000 اسم | أقل من 30 دقيقة |
| استخدام الذاكرة | أقل من 2 GB |
| استخدام CPU | أقل من 80% |

# سياسات الأمان وحماية البيانات

## 1. مبادئ الأمان الأساسية

### 1.1 الأهداف الأمنية

**السرية (Confidentiality)**
ضمان أن البيانات الحساسة لا يمكن الوصول إليها إلا من قبل المستخدمين المصرح لهم.

**التكامل (Integrity)**
ضمان عدم تعديل البيانات بشكل غير مصرح.

**التوفرية (Availability)**
ضمان توفر النظام والبيانات عند الحاجة.

**المحاسبية (Accountability)**
تسجيل جميع العمليات والوصول للبيانات.

## 2. تشفير البيانات

### 2.1 تشفير أثناء النقل (In Transit)
- استخدام TLS 1.3 كحد أدنى
- شهادات SSL موثوقة من جهات معتمدة
- تحديث الشهادات قبل انتهاء الصلاحية

### 2.2 تشفير أثناء التخزين (At Rest)
- تشفير الحقول الحساسة (كلمات المرور، معرفات المستخدمين)
- استخدام AES-256 للتشفير
- إدارة المفاتيح الآمنة

## 3. إدارة الوصول والمصادقة

### 3.1 المصادقة (Authentication)

**مصادقة OAuth**
- استخدام OAuth 2.0 لتسجيل الدخول الآمن
- دعم تسجيل الدخول الموحد (SSO)
- جلسات آمنة مع انتهاء صلاحية محدد

**كلمات المرور**
- استخدام bcrypt لتشفير كلمات المرور
- متطلبات قوة (8 أحرف على الأقل)
- إجبار تغيير كل 90 يوم

**المصادقة متعددة العوامل (MFA)**
- دعم التحقق برسالة SMS
- دعم تطبيقات المصادقة
- إلزامي للحسابات الإدارية

### 3.2 التحكم بالوصول (Authorization)

**نموذج التحكم بالأدوار (RBAC)**
- **Admin**: وصول كامل
- **User**: وصول محدود للفحص
- **Viewer**: وصول للقراءة فقط

## 4. تسجيل الأنشطة والتدقيق

### 4.1 السجلات المسجلة

| نوع السجل | المحتوى |
|----------|---------|
| سجلات الوصول | تسجيل دخول، محاولات فاشلة |
| سجلات العمليات | عمليات البحث، الباتش، التحميل |
| سجلات التغييرات | تعديل البيانات، الحذف |

### 4.2 حماية السجلات
- السجلات لا يمكن حذفها أو تعديلها بعد الكتابة
- استخدام بصمات رقمية للتحقق من السلامة
- الاحتفاظ لمدة 7 سنوات على الأقل

## 5. أمان البنية التحتية

### 5.1 أمان الخادم
- تطبيق تحديثات الأمان فوراً
- تفعيل جدار الحماية
- مراقبة مستمرة لأداء الخوادم

### 5.2 أمان الشبكة
- استخدام VPN للاتصالات الحساسة
- عزل قاعدة البيانات عن الإنترنت العام
- استخدام شبكة خاصة للاتصالات الداخلية

## 6. إدارة الحوادث الأمنية

### 6.1 خطة الاستجابة

1. **الكشف**: مراقبة مستمرة لأنشطة مريبة
2. **التقييم**: تقييم سرعة الحادث وخطورته
3. **الاحتواء**: عزل الأنظمة المتأثرة
4. **الاستئصال**: إزالة السبب الجذري
5. **الاسترجاع**: استعادة النظام للحالة الطبيعية
6. **الدرس المستفاد**: تحليل وتحديث السياسات

## 7. الامتثال والمعايير

### 7.1 المعايير الدولية
- **معايير FATF**: التوصيات الأربعين لمكافحة غسيل الأموال
- **معايير ISO**: ISO 27001, ISO 27002, ISO 9001
- **معايير البيانات**: GDPR وقوانين حماية البيانات المحلية

### 7.2 التدقيق والفحص
- فحوصات أمان ربع سنوية
- اختبارات الاختراق السنوية
- تقييمات الثغرات الأمنية

# دليل الاستخدام

## 1. البدء السريع

### 1.1 تسجيل الدخول
1. انتقل إلى موقع المنصة
2. انقر على "تسجيل الدخول"
3. أدخل بيانات اعتمادك
4. اتبع خطوات المصادقة متعددة العوامل

### 1.2 الواجهة الرئيسية
- **القائمة الجانبية**: الخيارات الرئيسية
- **منطقة المحتوى**: عرض المعلومات والنتائج
- **شريط المستخدم**: معلومات حسابك

## 2. الفحص الفردي

### 2.1 خطوات الفحص الفردي

1. انقر على "Screening" في القائمة الجانبية
2. تأكد من أن "Single" مختار
3. أدخل الاسم المراد فحصه
4. انقر على "SCREEN"
5. انتظر النتائج

### 2.2 فهم النتائج

| النتيجة | الوصف | الإجراء |
|--------|-------|--------|
| **MATCH** | تطابق قوي جداً | اتخاذ إجراء فوري |
| **POSSIBLE_MATCH** | تطابق محتمل | تحقق إضافي |
| **NO_MATCH** | عدم تطابق | لا يوجد مشكلة |

## 3. الفحص الجماعي (Batch Screening)

### 3.1 تحضير الملف
- صيغة Excel (.xlsx)
